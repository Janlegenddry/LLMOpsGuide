R-Fork：复制权重，不是复制整台 GPU

“R-Fork”在本页是参考材料中权重获取流程的名称：新推理进程向已有副本获取模型权重。它不是 PCIe 或 RDMA 标准的术语，也不等于操作系统 fork() 的完整语义。本页只演示一种以 GPU 显存作为源与目标、由目标端发起 RDMA READ 的加载路径；不声称所有实现都必须走这条路径。

图中左右两台服务器保留机箱、双 CPU 区、内存条、8 个加速模块、风扇墙和网卡端口，让数据路径与实物有对应。为避免遮挡，只突出其中一对 GPU/HCA；数量和槽位位置是教学布置，不是任何线上机器的拓扑快照。顶部机箱可打开，立体、俯视和正面视角可随时切换。

分清请求方向、数据方向与完成时刻

目标端提交 READ 请求，方向是目标 HCA → 网络 → 源 HCA；权重数据沿反方向返回，先由源 HCA 读取源 GPU HBM，再通过网络与目标 PCIe 路径写入目标 HBM。动画用蓝色表示请求、金色表示数据；移动光点是方向提示，既不是实际 TLP，也不表示真实分片大小或带宽。

控制面：目标加载器 → MR / QP / WR → READ 请求
数据面：源 GPU HBM → 源 PCIe → 源 HCA
                        ↓ RDMA 网络
        目标 GPU HBM ← 目标 PCIe ← 目标 HCA
完成面：完成状态 → 同步与可见性 → 加载校验 → Ready

MR（Memory Region）描述注册内存与访问权限，QP（Queue Pair）承载发送 / 接收工作，WR（Work Request）是提交的操作，CQE（Completion Queue Entry）报告完成状态。传输完成、GPU 可安全读取、模型初始化完成与对外 Ready 是不同边界。不能只因进度到 100% 就放行推理，也不能把单个完成项当成所有加载工作已完成。

GPUDirect RDMA 可以避免让 CPU 主存充当权重数据中转站，但 CPU 仍负责驱动、注册、提交和同步。是否可用还取决于 GPU、网卡、驱动、PCIe 拓扑与平台配置；也可能存在经主存暂存的回退路径。具体要求和内存顺序约束见 NVIDIA GPUDirect RDMA 文档。

故障演示不等于根因结论

切换到“生命周期风险”分支，可以看到传输未结束时 MR / 缓冲区生命周期失配，目标模型保持未就绪。演示选择在取消、drain 与同步完成后清理旧状态，重新登记并重传；不是在旧请求仍可能访问时强行释放内存。不同实现可以选择安全重试、回退或失败退出。

这种软件生命周期风险不必然产生 Malformed TLP，更不能单独证明 GPU、网卡或 PCIe Switch 有缺陷。两个设备位于同一个 PCIe Switch 下，也不等于它们共享同一条下行物理链路。定位异常时，要区分检测 / 报告端点、转发路径和真正的错误来源，结合 AER / CPER、驱动记录、完成状态以及可重复的对照实验判断。

本页没有复用参考文件中的内部文档链接、主机地址、设备 BDF、现场计数、驱动批次或推测性根因结论。页面中的进度、设备摆放和异常分支均为明确标注的教学场景。
