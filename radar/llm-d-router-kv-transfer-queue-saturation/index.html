llm-d-router 的 P/D 饱和度修正：等 KV 与等 Decode 不是一回事

原文 2026-11-05核对 2026-11-23

只从路由器队列项扣除正在拉取 KV 的等待，不抹去总队列。拆解 #4016 的阶段口径、scrape-lag 补偿和保护边界，并给出影子打分及慢传输/真饱和对照。

一、结论：等 KV 的请求仍在等待，但不一定代表 Decode 无算力

推导 / 教学示例

这次修改最值得借鉴的是指标分工：总等待保留给可观测性，路由器的队列项只扣除传输确已发起且未报告完成的那部分；传输未发起或已完成仍排队则保留。这样既不把传输等待直接当 D 算力饱和，也不把业务等待抹掉。

作者报告结果[1] ↗[2] ↗[4] ↗

正式证据是 #4016 于 11 月 22 日合入主干（4e58955），不是同日稳定版或生产性能结论。PR 提供定向测试，未提供受控 P/D 生产延迟、吞吐或成本数据。

推导 / 教学示例

优先做影子评分和双轨仪表盘，不建议直接降低容量阈值、屏蔽传输告警或改现有生产策略。尤其需要证明：当传输才是真瓶颈时，少过滤 D 不会把压力继续灌给 P、网络或 KV 分配。

二、背景：把总等待、等待阶段和调度容量分开

官方事实[3] ↗

vLLM 将引擎等待总数与按原因、按异步 KV load 阶段的分解分别导出。按原因的 deferred 是宽桶，包含 LoRA、KV transfer 等；按阶段有 waiting_to_start、in_progress、completed_waiting 三类，分别表示未启动、启动后未报告完成、已完成但尚未运行。

作者报告结果[1] ↗

在 P/D 分离中，D 侧可能已经接收请求，却在等待 KV；少量运行序列与较大等待队列可以同时存在。llm-d PR 指出旧 detector 把总量用于 saturation 和注入调度 profile 的 filter，可能把仍有计算空间的 D 排除。这个报告不将判定解释为引擎本身不健康。

推导 / 教学示例

传输“已启动未报告完成”可能包含排队、进展慢、回调延迟或拥塞，不等于链路流量一直在跑。只有对瓶颈目标与时间窗口做了约定，才能把这个桶用作一个较好的修正信号。

三、机制：扣窄口子集，但不能让在途补偿重复记账

作者报告结果[1] ↗[2] ↗

合并实现把可选 deferredRequestsSpec 编译到 extractor 映射。内置 vllm 匹配 stage=in_progress；合法 waiting 提取发生时才写 DeferredQueueSize，缺失/非有限的 deferred series 归零。若等待 family 不可用，这一分支不会产生新的 deferred 样本，不能解释为“确认没有传输”。同名自定义 engineConfigs 替换内置配置，没配 spec 就没有这条信号。

作者报告结果[2] ↗

记 W=原始等待、R=运行请求、L=producer 提供的已接入在途数、D=deferred 标量。有效 D 要满足 0≤D≤W，队列估计为 W−int(D)+max(0,L−W−R)；没有有效 D 不扣减，没有 producer 则没有 credit。计算项仍以整数请求数计。负值、非有限或大于 W 不应压低队列项。

推导 / 教学示例

教学例：W=8、R=2、L=12、D=5，credit 是 2，旧 queueDepth=10，新 queueDepth=5。若用扣减后 W=3 重算 credit，会误得 7 并重新补回 5；这是同一批请求已出现在 scrape 的原总量中。数字是示意，不是基准测试。

作者报告结果[2] ↗

饱和评分仍以队列阈值、KV 利用率阈值分别衡量并取较高项；同一 queueDepth 也用于过滤。队列项降到 0 不代表所有饱和条件解除：高 KV 使用和缺失/过期遥测仍可触发既有行为。具体阈值应从目标 profile 核对，不照抄文档示例。

五、取舍：避免假饱和，也要保护真正的瓶颈

推导 / 教学示例

扣减之后，原本跨阈值的 D 可能重新入选。若随后大量 KV 同时完成，队列会重新显形，形成短时拥塞；若某个到达率下 P/D 链路不稳定，更多准入还会推高传输在途或失败率。要在稳态、慢传输与完成突发三种场景都检查保护效果。

推导 / 教学示例

不应把该逻辑泛化成“所有因依赖卡住的请求都不算队列”。未发起请求还在等待 load 准入；完成后但未运行则可能真缺 decode 容量，LoRA 或 grammar 会占据服务等待而且不属于这次扣减对象。宽扣容易把实质队列掩盖。

推导 / 教学示例

独立 scrape 不保证端到端同步。除范围基本校验，还要验证 W、R、D 的实例范围与时间，新旧 dashboard 共享同一组原始指标但不覆盖彼此；必要时回退到原总量与显式不可信标签，而非静默填补产生乐观判定。

成功指标可以写成“在同等负载与失败预算内，降低被误过滤的健康 D 比例，并不恶化传输等待/超时”。用业务达标完成量作容量口径，用户有等待但被提前拒绝不能从分母中消失。

九、未验证：版本、协议、适配与效果仍须现场结算

待验证[3] ↗

文中阶段语义是 vLLM 的生产指标契约；不同框架或自定义 exporter 可能定义不同。需要对齐报告的作用域、采样粒度、请求身份与终态再移植。不能把本例当作具体线上故障诊断，也不建议直接替换 PD 调度参数。

推导 / 教学示例

建议沉淀一份可重复的决策样本：原样输入、旧/新公式、阶段归属、过滤原因和业务终态。它能用来评估任何声称“队列下降”的路由改动，而不依赖某一个路由产品。
