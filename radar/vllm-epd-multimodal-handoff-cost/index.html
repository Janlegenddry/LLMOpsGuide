vLLM 多模态 EPD：三段交付契约与每卡成本

原文 2026-11-11核对 2026-11-15

把布局元数据、E→P 编码张量和 P→D KV 拆开验收。重算 GB200 作者数据后，低并发更快不等于更省卡；H20 的共享复用结果也只回答复用问题。

结论：先证明交接正确，再为 E 池付卡费

推导 / 教学示例

值得设计的是两张独立的账：布局契约能否避免 P 重复处理媒体，以及增加 E 池后，满足首 token 与流式 SLO 的请求数能否覆盖全部部署成本。对已经做 P/D 分离的服务，E→P 的编码张量不是 P→D 的语言模型 KV；Mooncake Store 的共享命中也不是交付给 P 成功。

作者报告结果[1] ↗[7] ↗

作者在短答案、多页文档负载上比较 8 卡 PD 与 12 卡 EPD；在并发 16 时后者的首 token 尾延迟较低、整体 token 吞吐较高，但按全部 GPU 折算的吞吐反而下降。这个组合不支持“拆了 E 就一定更省卡”。

背景：从媒体文件到语言模型输入之间发生了什么

官方事实[1] ↗[5] ↗

预填充前还有媒体读取、预处理和模态编码。远置编码得到嵌入后，如果 P 仍收到原图，就可能再次做布局所需的预处理；这不等于执行第二次 encoder forward。仅元数据路径让 P 按模型要求重建位置，并通过独立连接器获取编码张量。

推导 / 教学示例

可把一次多图请求视为两种对象加一份索引：布局告诉 P 第几张图占哪些位置，张量给出该位置的向量，索引用于把两者拼回同一请求。批处理、切换副本或重试后，只检查形状相等不足以证明内容属于这些位置。

机制：布局、嵌入和 KV 分账

官方事实[2] ↗[3] ↗

Mooncake EC 的 TCP/RDMA 选择对应嵌入交付。共享输出复用是不同功能：E 可以从 Store 取出可复用张量，而交付到消费侧仍由连接器完成。当前公开指南的初始共享组合对模态、执行器、TP 和 LoRA 有明确限制；异步写入也不是跨实例的去重锁。

推导 / 教学示例

拆开观测三类完成事件：E 计算结束、张量交接完成、P 已消费正确张量。RPC 返回或缓存标志不足以证明后一个事件。若负载经 P/D 拆分，还要再观测独立的 KV 交付；不要拿 E 层的命中率解释 D 层的所有长尾。

H20 · 共享复用同节点 TCP，InternVL3_5-38B-HF，2E+4PD。预填充共享缓存后刻意改派图片到本地不命中的 E；128 个请求、512 张图，作者报告 P90 TTFT 由 1.656 降至 0.891 s。比较的是共享复用开关，不是 PD 对 EPD，也不是自然命中率或跨节点 RDMA。作者报告结果[1] ↗

推导 / 教学示例[7] ↗

低并发算账示例：每卡吞吐比等于 49135/39168 再乘 8/12，约 0.836。分母取全部部署卡，而不是只取忙卡或只取 P/D 卡。短输出的总 token/s 主要反映输入，不能替代生成吞吐或每请求成本。

取舍：何时先做 E+PD，何时保留共置

推导 / 教学示例

优先试验 E+PD 的条件是媒体阶段确实占据首 token 或挤占语言模型资源，且负载有足够视觉计算支撑独立副本。小流量、以文本为主或高局部命中时，额外排队、传输、跨服务失败点和空闲 GPU 开销未必划算。应使用相同硬件预算给共置基线同样的优化机会，再另做加卡后可达能力对比。

官方事实[6] ↗

昇腾主线文档提供 EPD 与跨 E 复用验证，但它不是 CUDA 图或 GPU RDMA 性能证明。核查 NPU 文档描述的模型、连接器、镜像和传输路径；在自己的版本上不能把同名选项视为同一实现。

生产：故障要停在出错请求，不能污染邻居

官方事实[1] ↗[4] ↗

作者与对应 PR 描述了仅元数据请求遇到远程编码缺失而无法本地补算时的隔离处理。带原媒体与只有元数据的两类请求，具备不同回退前提。

推导 / 教学示例

按独立证据归因：只在跨 E 后失败先看命中/身份/异步发布；E 已产出但 P 等待长先看连接器与消费侧队列；向量已交付但首 token 慢再看 P 的占位、预填充、KV 交接和 D 排队。不要用 HTTP 200 证明多图顺序正确，也不要把连接器成功直接当作用户观察到首 token。灰度以完整 E+P 配套单元切换为宜，回滚要能让后续请求转回可用入口，并明确飞行中请求的终态。

验收：四道门互不抵扣

阈值由同一业务 SLO 和基线提前给出；以下不是实测成绩
门槛测量口径停止条件依据
正确性固定可重复样本，检查媒体序号、嵌入契约和结构化结果；灰度前设定质量差异容限。出现媒体交叉、布局错配或不可解释的答案退化即停止。推导 / 教学示例
故障隔离在测试窗口计数仅一个预定请求的可解释终态、其他请求成功率与资源回落；观察恢复后新请求。单请求异常触发引擎退出、邻居异常或资源持续攀升即停止。推导 / 教学示例
延迟与容量客户端首 token 与真实流式间隔分开看；以全部发送请求为分母看达标率。只提高总 token/s 而恶化约定的长尾或成功率，不放量。推导 / 教学示例
成本同计量周期内，汇总所有部署 GPU/NPU 的设备秒与必要存储/网络开销，除以 SLO 达标完成量。同预算无收益则不启用；加卡仅在独立批准的容量目标下比较。推导 / 教学示例
