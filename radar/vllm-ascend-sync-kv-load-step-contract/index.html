Ascend 同步 KV 加载：本步依赖声明不能丢在调度器副本里

原文 2026-11-10核对 2026-11-11

BalanceScheduler 与 DyntraLBScheduler 恢复 has_sync_kv_loads 传播，让同步命中的加载在 forward 前启动。重点解释逐步逻辑或、异步请求准入、逐层等待以及正式标签与回补分支的不同证据。

结论：同步依赖必须先声明，才能先启动

推导 / 教学示例

外部缓存命中把计算变成了一个有前置数据依赖的任务。调度器不仅要决定“这个请求可以算多少 token”，还要告诉执行端“当前这次 forward 会消费刚恢复的 KV”。如果只保留 token 数，执行端仍可能选择适用于异步接收的延后提交路径；表面上省下了前向之前的主机开销，实际却把数据生产者排在消费者之后。

官方事实[1] ↗[2] ↗[3] ↗

冻结变更在 BalanceScheduler 和 DyntraLBScheduler 中补回逐步标志：每次 schedule 从 False 开始；同步外部命中请求进入 running 时置 True；构造 SchedulerOutput 时传递。Dyntra 保留字段兼容检测。

推导 / 教学示例

优先判断运行实例是否同时使用这两个调度器之一、同步外部命中以及会消费该 KV 的 forward。不要把普通本地前缀命中、异步 PD 接收或所有 Ascend 输出异常统一归到这条修复。

背景：命中信息不等于可读数据

推导 / 教学示例

可以把一次调度步拆成三个账本：逻辑上已计算的 token、当前显存页的内容、这一轮 worker 必须完成的加载动作。前两项并不天然同步。调度器根据缓存索引发现历史前缀，并不表示设备页此刻已经存有该历史前缀。能跳过重复 prefill 的依据，必须同真正的数据恢复相接。

官方事实[4] ↗[11] ↗

冻结的 worker mixin 先绑定连接器元数据，再按 has_sync_kv_loads 选择 start_load_kv 的调用位置：真值时在 yield 前启动，假值时在 finally 中启动。SchedulerOutput 的字段默认 False。

推导 / 教学示例

这里的“同步”是当前计算步对外部 KV 的依赖分类，并不承诺一次函数调用阻塞至所有层搬运完毕。逐层连接器可以先建立加载流水线，再由每层等待相应数据。因而源码证据支持“启动顺序被修复”，不能单凭一个布尔值宣称端到端数据正确性已经证明。

机制：逐步逻辑或，而非最后一个请求的状态

官方事实[2] ↗[3] ↗

同步外部命中至少要跨过两个条件：命中量大于零，且请求确实进入当前步的计算集合。两个修复点都位于异步分支的 continue 之后；异步命中会进入 WAITING_FOR_REMOTE_KVS，不为本步增加计算 token。

推导 / 教学示例

这个标志是一项集合性质：只要本步任一个已准入请求需要同步恢复，整步就不能采用“所有加载都放在 forward 后”的顺序。后面遇到一个异步请求，不能把先前的 True 重置为 False；下一步又必须重新初始化，不能让上一步的 True 泄漏成永久同步策略。混合负载恰好能暴露这两种相反的错误。

推导 / 教学示例

从依赖图看，修复增加的是加载启动到 forward 的先后边。它不新增网络重试，不决定缓存内容校验，也不替代某层的完成事件。若 start_load_kv 已在前面调用而输出仍错，应继续追踪层名、块映射、请求身份与等待事件，避免把所有恢复错误都归因到调度布尔值。

取舍：前置必要工作，保留可安全重叠的路径

推导 / 教学示例

只要当前计算依赖恢复内容，加载提交成本就不能靠错误排序隐藏。反过来，当请求仍在异步接收队列、这一轮并不读取其 KV 时，维持延后提交可以继续减少前向关键路径上的主机工作。正确修复不是全局打开同步，而是让选择与实际依赖相符。

推导 / 教学示例

混合步被提升为前置启动，并不意味该步的所有请求都要串行等待所有层或所有远端请求。具体并行度来自连接器如何批量启动、如何为每层提供完成条件，以及模型在哪里消费。若把该标志解释为“全局同步屏障”，会夸大开销，也可能诱发不必要的性能规避。

推导 / 教学示例

Dyntra 的字段能力检测只处理与不同 SchedulerOutput 结构的接口兼容，不是证明所有旧版本都具有相同 worker 时序。适配器、引擎与外部 KV 插件仍应作为一个可追溯的组合验收。

生产诊断：先找缺失的时序，再判断内容错误

推导 / 教学示例

诊断时把内容正确性与服务时延分开。网络吞吐正常不能证明读取发生在正确时间；同样，TTFT 变好也不能抵消答案对缓存冷热状态的异常依赖。

未闭合项：回补不是发布，单元测试不是设备验收

待验证

  • #21454 合入的是 release 分支；正式 v0.30.0 标签与已核对的 v0.32.0rc1 文件仍不可视为包含修复。后续标签、wheel 与镜像需要重新核对。

推导 / 教学示例

可迁移的教训是：复制调度器时，最容易遗漏的可能不是调度算法，而是连接计算与外部副作用的元数据。输出字段的默认值只保证接口能构造，不保证默认语义适用于每个复制出来的调度路径。
