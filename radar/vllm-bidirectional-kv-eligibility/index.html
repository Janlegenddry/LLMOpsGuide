推导 / 教学示例[1] ↗

10月12日的vLLM官方博客值得读，最有迁移价值的问题是：PD分离之后，怎样让上一轮decode已经算过的状态在下一轮prefill继续有用。

推导 / 教学示例

这不是“打开开关就提速”的故事。一次远端KV复用同时需要四项条件：找到正确的会话版本；新旧token历史相容；远端块尚在且可读；搬运的总成本低于重算。任何一项不成立，都应选择可解释的重算或失败处理，而非继续使用看似存在的块地址。

推导 / 教学示例

对H20团队，建议把它当作多轮PD服务的一套隔离实验题。对SGLang团队，可迁移的是资格判断、缓存寿命与成本度量方法，不能把vLLM参数当成SGLang现成接口。对Ascend910，本次没有后端可用性或性能证据，不能继承结论。

背景：分离计算之后，还要接回上下文

推导 / 教学示例

PD分离把两种资源曲线拆开：prefill面对大段输入，decode面对逐token生成。多轮应用却把它们重新连起来，因为下一轮输入通常含有上一轮生成结果。

推导 / 教学示例

原创例子：一个代码代理先读文件、生成分析，再接受测试输出。下一轮可能沿用完整历史，也可能先摘要历史、删除内部思考、规范化工具调用。两者都叫“同一会话”，但并不对应同一条token序列。会话标识只回答“属于谁”，不能独自回答“这些KV对应哪一段输入”。

推导 / 教学示例

因此，“缓存存在”至少有三个不同含义：控制面还记得地址；数据面还保留内存；语义上仍对应这次计算。只看命中率，会把三者混为一谈。

机制：两条数据路径，一道资格门

官方事实[3] ↗

固定v0.29.0源码表明，pull调度器先计算远端可提供、且尚未由本地覆盖的token数量，再与阈值比较；并不是拿总prompt长度直接决定搬运。decode在合适完成状态下延迟释放块，并把远端请求、块位置、计算长度及过期信息交出去。

官方事实[4] ↗

worker会在带有远端过期信息时结合时钟偏移与安全余量判断是否拒绝读取；若元数据没有过期字段，该检查返回“不判定过期”。这证明存在一条防护路径，不证明每个路由器都完整转发了字段，更不证明所有失败已自动恢复。

官方事实[5] ↗

示例proxy按conversation_id保存位置元数据，后续请求取出并消费它，再转交给prefill。固定缓存对象保存的字段是参数与时间戳；检查的处理路径没有验证前后token历史。 这是一份流程示例，生产路由仍需明确内容一致性、身份隔离和并发分支规则。

推导 / 教学示例[3] ↗[4] ↗[5] ↗

读图时应区分两种箭头：实线表示P与D之间的KV数据，虚线表示路由器携带的位置与身份元数据。资格门是拟议生产设计，不是示例proxy已有的完整能力；保留块会占用容量，图中不表达任何测得的收益。

成本：省掉计算，可能留下另一份账单

推导 / 教学示例

原创成本框架：一次复用的收益应由“避免的prefill计算”减去“元数据协调、网络传输、排队变化、保留内存导致的机会成本”来衡量。各项可能重叠，不能将分段日志直接机械相加，当成端到端关键路径。

推导 / 教学示例

保留更久通常提高再次使用机会，也让没有返回的会话继续占据容量。只测低并发TTFT，很容易错过新请求排队、decode可用块减少和尾延迟上升。应在固定硬件预算下同时测完成请求量、SLO内有效吞吐和保留块峰值。

推导 / 教学示例

阈值也不是硬件无关常数。相同token数量，对不同模型的KV字节数、不同精度、不同链路拥塞都不同。建议先按“避免的计算时间/传输字节”建观察表，再决定是否需要比固定token阈值更细的策略；这里并未声称框架提供了自动成本优化器。

生产取舍：把安全退化做成可观测路径

推导 / 教学示例

建议将状态分为候选、已核验、读取中、已完成、已放弃五类。记录为什么放弃：本地已覆盖、历史变更、元数据缺失、期限接近、远端不可达、收益不足。这样既能解释MISS，也能识别错误使用了缓存的情况。

推导 / 教学示例

拟议最小观测：匿名会话版本/turn序号、模型与模板版本、路由代际、远端engine/request身份、可复用token、实际字节、P和D的读取方向、保留块占用、拒绝原因、重算代价、TTFT及TPOT。不要记录真实提示词或缓存内容来换取方便。

推导 / 教学示例

并发分支特别需要明确：同一会话同时发起两条后续请求，或者重试先于旧响应抵达，哪个版本可以消费缓存？固定示例的pop说明单次读取会消耗映射，同键put会覆盖。不能因此推断已有完整版本控制。生产实现可以先串行化同一会话、对分支使用新版本键；具体方案应按业务要求验收，本文未实施。

推导 / 教学示例

历史被压缩、工具调用被重写、thinking被剥离时，安全默认应是停止使用不再匹配的远端状态。可保留多长共同前缀，需要经token级和块级验证，不能在文本看似相同的基础上猜测。

实验：先补齐复现包，再把基线恢复正常

推导 / 教学示例[8] ↗[9] ↗[15] ↗

本轮找到博客网页脚本链接404，但同一官方仓库中的三个脚本可读取。因此应说“网页分发链接存在缺口，仓库可取”，不能说“没有脚本”。

推导 / 教学示例[8] ↗[9] ↗

源码静态检查另有一个实验卫生疑点：sweep默认等待20秒，注释说等待D保留块到期；启动脚本默认保留期限480秒。 20秒等待本身不能证明旧点已清空。但块可能因已消费、之前已老化或其他生命周期路径而释放，不能据此断言实际一定残留，更不能否定作者成绩。每个点应记录占用归零/稳定证据，或使用隔离重启并明确冷暖条件。

作者报告结果[8] ↗[9] ↗

按所读作者复现脚本，默认负载为10个会话、每会话10轮，每轮用户输入150、输出目标300 token，2个客户端、最多10个活跃会话；扫初始前缀长度。应区分初始前缀长度与逐轮增长的实际输入长度，使用逐请求token计数归组。脚本提供暖身配置，但本轮未运行，不声明所有图表遵循某一推断的统计口径。

出现错误缓存复用、跨请求污染、读取仍在进行时重用内存，应立即停止推广。若只在prefill本地缓存关闭时获益，也并非实验无价值，但结论必须限于迁移、驱逐或缺乏本地局部性的工作负载。

下一步：值得做的是一个小而完整的资格实验

推导 / 教学示例

优先完成E0与E2，再做E1。先回答“这次读回来的状态正确吗”，然后问“真实本地命中率下还省多少”。最后扩到容量、分支与故障。不要同时换模型、通信后端、量化和调度策略，否则收益和回归难以归因。

推导 / 教学示例

本轮建议：保留为高价值工程解读候选；不直接推荐线上开关，不给H20/Ascend性能承诺，不把官方博客中尚需补丁的复现路径写成已完整发布。它最有用的启发是，把远端KV从一个“命中计数”，重新看成有身份、语义、寿命和价格的计算状态。
