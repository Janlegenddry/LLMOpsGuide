一 结论与应采取的判断

官方事实[1] ↗

vLLM 于 11 月 5 日合入 #65598，固定提交 29e58d1。补丁把 TRTLLM prefill 的 query offsets 改为 builder 持久 int32 缓冲，并以带 out 参数的减法更新。

推导 / 教学示例

这条变化值得进入独立草稿模型的升级检查清单。排查应先确定实际执行了哪种 attention 路径，再证明图读到的地址和当前写入的地址相同。只看新 metadata 的数值正确，可能漏掉另一份仍被图引用的旧存储。

待验证

本文不建议为了获得未测收益而直接升级生产。优先完成制品包含核对、地址与内容测试，再做真实图重放和服务验收。没有运行模型、GPU、上游回归测试或用户环境，也没有独立性能数据。

二 草稿预填充为何进入图捕获

官方事实[5] ↗

固定 standalone AR 实现为展开后的 prefill 建立单独图管理器，宽度与 speculative steps 加 2 对应；每次先构建 attention metadata，再在 FULL 分支调用 run_fullgraph。

官方事实[6] ↗

共享草稿 metadata 构建函数在 FULL 下使用图的 padded token 数，并按 padded request 数构建输入；PIECEWISE 或 eager 使用实际 token 数。

推导 / 教学示例

因此“正在生成”不能替代后端的 prefill/decode 分类。一次逻辑上的解码轮次内部，可以有负责读取一段已知 token 的预填充工作。应分别记录逻辑阶段、每请求 query 宽度、后端分类和图模式，否则故障容易被错误归入普通单 token decode。

推导 / 教学示例

教学例子：设某个解码分类阈值为 4，当前每个请求实际需要处理 5 个 query token。批次即使等长，也越过了该阈值。这个例子说明等长条件与路径条件是两个不同的判断；数字仅用于教学，不是性能样本或所有配置的默认值。

作者报告结果[8] ↗

PyTorch 2.15 文档说明：重放沿用捕获的指针参数，应用应保留输入输出张量并原位更新数据；同一图也要求固定的大小和布局。

三 从偏移值到存储寿命的完整机制

官方事实[2] ↗

固定后端把有效 prefill offsets 视图传入 TRTLLMPrefill.cum_seq_lens_q，随后交给 trtllm_batch_context_with_kv_cache。该分支排除 DCP。另一个 FP8 KV 加非 FP8 query 分支仍对 block tables 调用 contiguous。

推导 / 教学示例

query offsets 是分段边界，不是 KV 实体。对某个合成批次，若完整边界为 [0,1,2,7,12]，前两个请求各占一个 query，后两个各占五个，则后半段的局部边界是 [0,5,10]。减去前缀起点的算术正确，只回答了“这次算出了什么”，没有回答“图最终从哪里读取”。

推导 / 教学示例

可以把正确性拆成四个独立条件：边界值符合本轮请求；存储地址与图记录一致；存储仍存活；写入完成后才允许对应读取。任意一个条件缺失，都不应把其余条件的通过当成替代证明。

推导 / 教学示例

持久缓冲改变的是所有权和地址合同。metadata 中的视图应按本次执行窗口使用，不能把它当作永远不变的历史快照。调试时若要比较两个时刻的值，应在各自有效时刻另存副本；保留旧视图本身不会冻结其内容。

推导 / 教学示例

同理，地址一致也不会自动创建跨流依赖。若未来引入并行请求处理或重叠重放，需要重新验证同一缓冲何时可写、何时读完。这里提出的是扩展设计的验证要求，并非宣称当前实现存在并发竞态。

作者报告结果[7] ↗

作者报告：1×GB200、runner V2、Qwen3-8B/0.6B、K=3，GSM8K 1319题、贪心解码；修复后并发32/256准确率均0.886、平均接受2.44，与PIECEWISE参考一致。作者明确未测 FP8 KV 加非 FP8 query 的相邻风险。未独立复现。

官方事实[3] ↗

新增测试用 monkeypatch 强制选择 TRTLLM，query 宽度为实际阈值加一；逐轮检查数值，并在最后要求地址集合只有一个元素。未执行此测试。

推导 / 教学示例

保留旧输出有很强的鉴别价值：否则旧张量释放后，分配器可能恰好把同一地址重新给新张量，让“地址没变”的观察成为偶然事件。相反，保留所有历史视图又会共享持久存储，所以数值检查必须发生在每轮有效窗口，不能事后把所有视图当历史证据。

推导 / 教学示例

相同准确率和平均接受数是有限任务集上的支持证据，不能证明每个 attention 输出、每个草稿 token 或随机采样序列完全相同。也不能由这些数字推导吞吐、TTFT、ITL 或 GPU 成本改善。

五 硬件适用范围与实现取舍

官方事实[4] ↗

固定 utils 仅为 SM100 family 开启 TRTLLM prefill；SM90/SM12x 在此只支持 XQA decode。路由还检查禁用配置、batch-invariant、cubins 可获取性、头数整除与 DCP。

推导 / 教学示例

因此不能把这篇报告当作 H20 上某条路径已修复的承诺，更不能迁移为 Ascend 内核结论。对其他设备，有价值的是验证“真实分支、设备地址、存活期和读写顺序”的方法；适用性仍须由对应实现证明。

推导 / 教学示例

按 int32 元素计算，容量 M 的一份偏移缓冲理论数据字节数为 4×(M+1)。例如教学容量 256 对应 1028 字节。这个算式不含 allocator 对齐、多个 builder、图池和其余持久张量，不能当作总显存增量测量。

推导 / 教学示例

保活通常用少量常驻内存换取明确的地址寿命，但也使同一存储的复用规则更重要。不能把不断追加历史张量引用当作生产修复，那可能只是把旧地址保住，同时制造随请求增长的内存占用。

推导 / 教学示例

临时切换图模式可作为隔离实验的对照，而非本文给出的生产处方。改变图模式可能影响 CPU 开销、调度和容量；应锁定其余变量，并保留可恢复配置，不能把“关闭图后不崩”直接等同于已锁定根因。
