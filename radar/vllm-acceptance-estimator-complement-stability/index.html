一 结论与升级判断

官方事实[1] ↗

vLLM 于 11 月 6 日合入 #65229，固定提交 61968a5。补丁修正自适应验证所用接受率估计器的尾量计算，并补充小尾量、多词表块及并列最大值测试。

推导 / 教学示例

对已实际启用此估计器的服务，优先检查置信特征是否被错误压到上限，再判断验证预算、在线拟合和服务效率是否改善。数值修复值得独立验收，但它不是新的接受判定器，也不直接承诺输出质量、接受率或吞吐提升。

待验证

本次完成源码核对和一组 CPU 标量 binary32 舍入教学演示。没有执行上游测试、Triton kernel、GPU、模型推理或端到端服务实验；正式制品包含和目标平台效果仍待验证。

二 从草稿置信度到验证预算

官方事实[4] ↗

固定 speculator 仅在相关开关生效时创建估计器；预测接收 logits、请求映射、草稿位置及温度。目标模型给出上一轮结果后，应先观测再进行会覆盖特征的下一次 propose。

官方事实[5] ↗

配置中的 enable_adaptive_verification 默认关闭，并明确拒绝需要 logits 的估计路径与 use_local_argmax_reduction 同时开启。具体方法的支持还须核对所选 speculator。

推导 / 教学示例

这里至少有三种不同的“概率”：草稿分布对词表 token 的概率、估计器输出的下一位置被接受概率、真实验证产生的接受事件。草稿模型对某个词非常确信，不代表目标模型一定认同；因此把草稿分布直接命名为真实接受率，会把代理信号与监督结果混为一谈。

推导 / 教学示例

可以把估计器看作验证预算决策之前的一层测量。测量损坏时，后续拟合可能部分补偿，却无法仅凭同一个饱和值重建被抹平的区别。修复测量仍不保证策略在全部负载上更快，因为额外验证成本、模型一致性、批处理和目标模型耗时共同决定最终收益。

推导 / 教学示例

不要仅因服务使用了投机解码便认定补丁命中。应记录 runner、draft 方法、是否采用专门 confidence head、是否实例化 OnlineAcceptanceEstimator，以及真正执行的预测调用。H20、H100、Blackwell 或 Ascend 的型号名称都不能替代这条路径证据。

三 为什么先加一再减一会破坏特征

官方事实[2] ↗

最终实现为每个 4096 词表块保存局部最大值和排除一个最大项后的指数和。全局选择一个最大块，统一尺度并补回其他块的最大项，最后计算负对数、限幅到 ±40，再送入 sigmoid。

推导 / 教学示例

以下是原创数学推导。设已按正温度缩放的 logits 为 x，最大值为 m，选中一个最大 token 的位置 i。令 S 为所有 j≠i 的 exp(x[j]−m) 之和，则最大 token 概率为 1/(1+S)，其 odds 为 1/S，log-odds 为 −log(S)。注意 S 是相对最大项的尾质量，不是已经归一化的尾概率；归一化尾概率应为 S/(1+S)。

推导 / 教学示例

实数代数允许先算 1+S 再减 1，浮点运算却不保证可逆。在 binary32 的 1 附近，相邻可表示数之间有固定间隔。若 S 比这个尺度小得多，1+S 会舍入为 1；事后相减得到 0，随后负对数趋于无穷，限幅才把结果变成有限的 40。因此“没有 NaN”和“结果在允许区间”都不足以证明特征正确。

推导 / 教学示例

分块计算还有独立的身份问题。每块先去掉一个局部最大项，只是一种中间表示；全局目标并不是每块各去掉一项，而是整个词表只去掉一个 token。把各块相加时，必须恢复非选中块的局部最大项，并用 exp(m_b−m) 把它换到共同尺度。

推导 / 教学示例
原创记号，非可执行内核
E_b = 块 b 内排除一个局部最大 token 后的相对指数和
s_b = exp(m_b - m)
b*  = 任意一个含全局最大值的选中块
S   = sum_b E_b * s_b + sum_(b != b*) s_b
f   = clamp(-log(S), -40, 40)
推导 / 教学示例

若恰有 k 个并列最大 token，且其他质量可以忽略，排除一个后留下 k−1 个单位项，特征就是 −log(k−1)。双最大得到 0，三个最大得到约 −0.693。若按数值相等把所有最大值都删掉，会把歧义输入错误描述成极端确定；若每个并列最大块都排除一个，也会造成另一种多删。两类错误需要不同测试布局。

推导 / 教学示例

也不要把精确特征简化为 top-2 间隔除以温度。其余词表项的数量和分布同样进入尾质量；只有一个竞争者占主导的特殊情况下，间隔近似才可能足够。温度变化、词表大小和尾部分布应分开设计实验。

五 数值修复的适用边界

推导 / 教学示例

本报告关注估计器的一个特征，不修改真实目标模型分布，也不审计整套 rejection sampling。即使预算选择依赖前缀信息而非当前抽中的 token，整条服务链仍须检查随机数、温度、截断位置和接受逻辑，不能由局部公式推出全系统无偏。

推导 / 教学示例

相同的特征误差在不同拟合参数下会有不同影响。sigmoid 已接近饱和时，大的特征偏差可能只造成很小的概率差；在线拟合更新又会改变斜率和各位置截距。因此必须同时观察特征、预测、实际标签和截断深度，不能只比较参数中的一个数。

推导 / 教学示例

把所有计算改为 FP64 不是本文建议的默认方案。应先选择避免不必要消减的计算表达，再用高精度的独立参考检查它；是否需要更高精度、补偿求和或特殊处理，取决于实际误差、设备支持和成本。

推导 / 教学示例

并列值、全词表无有效质量、非有限 logits 和异常温度不是同一个问题。正常输入上稳定求和，不等于任意 NaN、+inf 或全 −inf 输入都有合适的服务语义。这里不声明补丁新增了这些异常输入合同，它们应分别按上游允许的输入范围验收。

推导 / 教学示例

H100 上作者测试不构成 H20、XPU、ROCm 或 NPU 的交付证据。可迁移的是“排除一个位置、统一指数尺度、独立参考”的检查方法；设备代码、编译器和模型支持仍须逐一证实。
