SGLang 草稿上下文 KV 的坐标边界：FULL 行号不能代替窗口行号

结论：先保证草稿写入坐标属于当前层

推导 / 教学示例

值得优先检查的是“能正常跑完但写错行”的风险。将目标模型与草稿模型放进共享 KV 存储后，同一个 token 的语义身份并没有保证它在每个子池中占用相同的物理行。升级时应先证明层、子池、行号和有效前缀四者一致，再比较接受率或延迟。

官方事实[1] ↗

#48001 修改路由、DFLASH、DSPARK 及回归测试：前缀写入不再只调用池级入口，调用链显式携带窗口位置。合入差异包含七个文件；这不是吞吐提升公告。

推导 / 教学示例

对工程读者最有用的决策是建立两项门槛：混合层的写集必须正确，不受支持的存储组合必须尽早拒绝。二者不能由模型加载成功、一次生成正常或一次性能提升代替。没有相关路由配置的部署，不应仅凭补丁标题就宣称需要紧急切换版本。

背景：共享存储不等于共享坐标

推导 / 教学示例

草稿模型消费目标模型特征时，需要把这些特征变成自己后续注意力读取的 K/V。这里讨论的是这一步上下文物化，不是只把已接受的 token ID 接到输出字符串后面。一次投机迭代还会区分可提交前缀和未接受候选，因而“写在哪”与“哪些候选可写”是两道不同的约束。

官方事实[7] ↗

IterationIds.write_ids 按 reader 和 IdSpaceKind 返回该子池的写入位置；不存在的子池返回 None，位置结果按空间键缓存。它也支持在一个写入窗口中选列。

推导 / 教学示例

建议把行号视为带命名空间的坐标：FULL 的第 12 行与窗口的第 12 行可以位于不同视图，窗口中同一 token 也可能在第 3 行。整数值看起来合法，只说明某次数组访问可能没有越界，不能证明读写对象正确。这里的“物理行”是存储池索引，不能直接等同于裸 GPU 地址。

推导 / 教学示例

本文的 unified 指目标与草稿 KV 存储及其子池组织，不把这一特性解释为 CUDA 统一虚拟内存的按需分页。是否跨设备、是否卸载、是否发生页面迁移，要分别查部署配置与实际执行证据，不能从 flag 名字推断。

机制：先选所属子池，再限制有效前缀

官方事实[2] ↗

KVLayer.store_prefix 对非 plain 路径先调用 _write_loc，再把对应视图层号传给前缀写入函数。_write_loc 对 owner 层选择 owner/full 坐标，对其他层要求存在窗口坐标；缺失时直接断言，而不是默用 FULL 行号。

官方事实[3] ↗

DFLASH 的 _draft_write_ids 增加 kind 参数。普通上下文追加和验证后的前缀提交都把窗口位置向下传递；窗口位置存在时必须与主位置形状一致。逐层与 fused helper 回调都进入同一个层路由写入入口。

官方事实[5] ↗

DSPARK 注入器在预填充及带迭代计划的注入中取得窗口坐标，并以 int64 移到目标设备，再交给模型的上下文 KV 写入。验证路径把当前迭代计划继续传入，避免只留下主位置向量。

官方事实[4] ↗

DSPARK 原有融合内核只接受一套位置向量；布局检查发现任一层不属于 owner 时返回 None。后续逐层路径仍可处理不同子池的位置。这里退出的是一条单位置融合路径，不是所有投影融合，也不是禁用整个 DSPARK。

推导 / 教学示例

原创例子：请求甲的两个候选在 FULL 中位于 12、13，在窗口中位于 3、4；本轮只允许提交第一个候选。正确写集应分别落在 FULL 的 12 与窗口的 3，两个第二候选槽都保持原值。若只修正提交长度，窗口仍可能写到 12；若只修正坐标，未接受的第二候选仍可能污染下一轮。这个例子仅用于解释不变量，数字不是上游测试或实测结果。

取舍：正确路由可能改变快速路径选择

推导 / 教学示例

共享存储减少重复管理，并不意味着所有层都能继续使用相同的融合约束。融合省掉的调用与中间步骤，往往建立在布局、形状或坐标一致的前提上。当这些前提不再成立，保留融合可能比回退更危险。评价修复时，应分别记录路径选择和端到端时延，不把任一慢路径出现直接判为回归。

官方事实[8] ↗

相邻 #48002 在绑定 CP 策略后拒绝 unified memory 与 sharded-padded CP KV 的组合；错误要求移除其中一个选项。配套单测让该 CP 条件成立时，统一池失败、静态池可继续。这个补丁没有宣告新增该组合支持。

生产诊断：从症状回到最早分歧的写集

推导 / 教学示例

以下都是拟议诊断假设，不是已证实的线上事故。症状可能是接受率突降、重复前缀时输出变化或并发下偶发错误，但这些表现也可能来自采样、模型兼容性或其他缓存路径。只有找到最早出现差异的 KV 写入，才能把问题归因到本修复范围。

推导 / 教学示例

效率分母必须统一。建议同时记录整段观测窗口的墙钟时间与实际交付给客户端的 token 数；草稿提出、验证计算和最终提交是不同计数，不能用更多候选 token 充当更高有效吞吐。若发生回退，性能比较需要解释回退比例而不只是给一条均值。
