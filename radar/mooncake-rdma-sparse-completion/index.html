推导 / 教学示例

该负载提供了一个可检验假设：链路尚有余量时，CPU 处理大量完成记录可能限制进展。若服务实际每批只产生少量 WR，或瓶颈是网络拥塞、GPU 计算、调度排队，减少通知不一定带来同等级收益。不要把“同为 H20”当作负载相同。

机制：少量硬件通知，仍逐项完成软件结算

官方事实[4] ↗

信号间隔取 min(interval, max_wr/2)，并保证每次 post_send 链的最后一个 WR 带信号。FIFO 按 QP 保存提交顺序；收到某个完成项时，只取出从队首到该项的前缀，后缀保持在队列中。半 SQ 上限用于分批释放发送槽；链尾信号才避免整链全为无信号项。

官方事实[5] ↗

提交路径按所有已提交 WR 扣 CQ 额度，而非仅统计带信号项。部分 post_send 失败时，仅已成功提交的前缀进入 FIFO；启用 FIFO 且存在该前缀时，端点进入销毁流程。

官方事实[6] ↗

poll 路径把一个硬件完成展开为多个软件完成。当前项保留硬件状态；它前面的项在当前状态为 WR_FLUSH_ERR 时也标 flush，否则标 success。CQ outstanding 按实际退休 WR 数量扣减，不按本次 poll 出来的 CQE 数量扣减。

推导 / 教学示例

以下两幅图分别解释正常完成和部分提交失败，不表示 P/D 数据流或实测时序。

推导 / 教学示例

图 A：同一 QP 的一条五项 post_send 教学链 W1–W5，interval=3，max_wr 至少 6。 - 提交轨：W1 无信号 → W2 无信号 → W3 周期信号 → W4 无信号 → W5 链尾信号；五项全部占用发送/CQ账本额度。 - 硬件通知轨：此刻收到成功 CQE(W3)，只画本次处理的一条通知，不画 W1/W2 成功 CQE；W5 的链尾完成通知属于后续处理。 - 软件退休轨：FIFO 前缀 W1/W2/W3 → 三项软件结算 → 释放三份额度。 - 独立边界：W4/W5 留在 FIFO；W3 的完成不授权退休它们。 - 注意：箭头表达单 QP 提交和结算关系，不表达跨 QP 全局顺序或硬件时间比例。

推导 / 教学示例

图 B：部分提交失败的教学链，interval=3，max_wr至少6，W1/W2均无信号。 - 拟提交 W1、W2、W3（W3原本是链尾信号）；post_send 在 W3 处失败。 - 已提交 W1/W2 → FIFO 保存 → 端点销毁请求 → 等待 provider 的 flush CQE → 本次尝试退休并按 flush 状态处理 → 有界重试或重试耗尽后失败；FIFO 退休不等于整个请求已经终态失败。 - 未提交 W3 → 失败列表；不得与已提交分支混画成硬件执行成功。 - flush 证据、请求最终状态及资源最终归零画为空心验收节点，表明没有本站硬件验证。

推导 / 教学示例

中心不变量可表述为：每个真正进入硬件的 WR，必须有唯一的软件结算归属；通知合并不能变成生命周期合并。一个成功 CQE 可以在限定顺序下作为前缀完成的证据，但错误路径仍可能为许多先前不带信号的 WR 生成完成记录。成功路径省通知，并不意味着失败路径的通知峰值也按同一倍数减少。

取舍：最有价值的是匹配瓶颈，不是把 N 调到最大

官方事实[11] ↗

该选项仅适用于 classic RdmaTransport。interval>1 要求 provider 对失败/flush 的无信号 WR 仍产生 CQE；不满足应保持默认 1。无信号 WR 在相应 CQE到来前仍占用 SQ，较大间隔可能需要较大的 MC_MAX_WR。

作者报告结果[12] ↗

NVIDIA RDMA 编程手册说明 CQ 应持续轮询；overrun 会使 CQ 停止并产生 CQ_ERR。这提供容量审视的通用背景，不构成对每个 provider 的认证。

推导 / 教学示例

更大 N 同时改变正常完成通知密度、额度释放节奏和故障结算依赖。短链因链尾总带信号，未必达到理想的 N 倍压缩。应用每次只有一个 WR 时，也不能因配置为32便预期32倍减少。每个 QP 的链长分布、实际信号比例和CPU忙碌点，比单独记录配置值更重要。

推导 / 教学示例

该机制没有减少 payload 字节量，也没有合并逻辑KV块。它与增大消息、合并切片、调大SQ深度是不同干预变量。A/B若同时改后三者，就无法判断收益来自通知减少还是排队容量变化。测试应保留“仅改 max_wr”的对照，而不把作者最终配置直接复制成最佳实践。

生产：用可证伪的故障假设替代空泛稳定性

推导 / 教学示例

以下均为原创诊断假设，不是已发现的现网故障。

推导 / 教学示例
  • 传输已经完成，任务却长期挂起。可能是错误路径未提供预期 CQE，或端点状态/账本未收敛。保存按QP的最后提交ID、信号标志、CQE状态、FIFO深度与端点状态；以安全隔离环境的故障注入建立证据，不先责怪网络带宽。
  • 正常压力下更快，断链时CQ报错。检查是否有人依据平均CQE压缩率下调容量或提高并发，导致最坏完成风暴超过预算；对照全部在途WR与CQ额度，不只看成功CQE计数。
  • 同一请求重复结束或资源提前释放。核对一个slice的提交、退休、重试和释放代次；仅比较指针地址可能把重用后的对象误认成同一任务。需追踪稳定逻辑ID与generation，这是一项建议的观测设计。
  • CPU轮询占用下降但P99 TTFT变差。检查小批任务是否被大批退休工作抢占、发送槽释放是否更突发，并分别记录服务排队与传输完成时间。通知减少不保证公平性提高。
  • 参数已配置但结果无变化。先核对实际库路径、构建SHA、后端、配置日志和带信号比例；不要只用环境变量截图证明特性命中。
