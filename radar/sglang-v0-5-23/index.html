SGLang v0.5.23 正式发布：把失败 ACK、投机参数和运行依赖纳入升级门禁

推导 / 教学示例

新变化是正式发布已经发生，不再只是一个可见标签。对 H20 运维，优先级应是确认产物身份、清除失效启动参数、验证 P/D 失败后的资源交接，再评估模型与负载对应的收益。把“官方发布”和“我方可安全升级”拆成两道判断，才能避免一次变更同时混入框架、依赖和优化开关。

官方事实[1] ↗

发布清单列出 #45973 延迟释放失败保护以及 #45043 删除 speculative-skip-dp-mlp-sync；默认 NVIDIA 镜像入口为 CUDA 13。

推导 / 教学示例

特别注意：NIXL 最终源码不是所有 ERR 一律不 ACK。它区分提交被拒绝、状态未排空，以及已 settle 的失败。Mori 的 Failed 状态走另一套 poison 判断。按初始 PR 标题概括所有后端，可能直接误导故障验收。

推导 / 教学示例

下文机制解释依赖冻结源码，不把后续 main 修复算进该版本；发布页中的其他硬件基准也不转化成 H20 收益承诺。

背景：一次升级跨过软件身份、协议责任和服务预算三层

推导 / 教学示例

版本号解决“准备运行哪份软件”，协议解决“谁还可能访问哪块资源”，SLO 解决“用户得到怎样的服务”。三者相互影响却不能相互证明。一个异常请求结束，仍可能留下异步写入；一个补丁合入，仍可能没有进入镜像；一次吞吐提高，也可能来自更长排队或较低成功率。

推导 / 教学示例

原创教学场景：请求 A 在 D 侧占有页 X，P 已向 X 发起写入。A 被取消后，新请求 B 很快获得同一页。若释放依据只是业务失败而不是访问责任结束，B 的内容可能被迟到写覆盖。这个例子解释为何释放确认需要比“请求报错”更强的证据，不代表已在用户环境观察到该故障。

推导 / 教学示例

同样，升级脚本里保留旧投机开关会让参数兼容性成为独立故障面。即使删掉开关能够启动，也还需要检查默认行为是否符合原有并行布局，而不是把启动成功当作性能与正确性都未变。

机制：数据写入完成与控制确认必须分别建模

官方事实[2] ↗

NIXL _await_handles 返回 settled 与 any_failed；状态读取失败返回未排空/失败。worker 对 _NixlPostError 且启用延迟释放的路径 poison；不能排空的路径也 poison。已 settle 的其他异常可以递减 outstanding 后尝试 ACK。

推导 / 教学示例

因此“句柄计数为零”“所有可见句柄已 settle”和“拒绝的提交绝无后续写入”不能混作同一证据。最终代码对 post 拒绝单独保护，正是因为该提交不一定出现在已保存的 handles 中。工程验收应覆盖失败发生位置，而不能只向同一个 status 字段注入 ERR。

官方事实[3] ↗

Mori 在正常完成检查及 drain 路径检查 Failed() 并 poison；递减 outstanding 和后续 _arm_abort_ack 都检查 poisoned room，防止较晚到达的取消通知绕开保护。

推导 / 教学示例

poison 代表放弃这条提前确认路径，不是物理取消 DMA 的证明。延迟释放回退仍需要按实际后端、网络和分配器验证；不能仅延长超时就宣称跨请求污染风险已消失。

推导 / 教学示例

这里采用最终标签源码而非 PR 的第一版补丁作为运行语义依据。单测提供一个重要的反例设计，但 mock 的传输状态不等于设备上的完成事件。本文没有复现发布页基准，也没有把社区问题报告认定为已确认现网根因。

取舍：保守释放需要容量预算，优化收益需要可比负载

推导 / 教学示例

停止提前 ACK 会把一部分异常请求的资源保留到回退路径。这是正确性与故障期容量之间的真实取舍：不能因占用升高就移除保护，也不能以“安全优先”为由忽略积压是否耗尽整个服务。更合理的做法是独立观测 poison 数量、保留页峰值、释放收敛时间和受牵连请求数。

推导 / 教学示例

原创预算示例：若单位时间出现 n 个异常房间，每个平均保留 k 页，额外驻留时间为 t，则稳态额外保留量可先用 n×k×t 做量纲检查。这不是该引擎的性能模型；突发、共享页、限流和回退并发会破坏稳态假设，真实容量必须由观测确定。

推导 / 教学示例

参数删除减少了一个显式选择，也要求配置仓库重新核对行为。不能为了保持旧 benchmark 数字，悄悄恢复被删除的同步绕过路径。若吞吐下降，应先拆分调度、通信等待和有效接受 token 的变化，再判断是否构成回退。

推导 / 教学示例

发布页列出的特定 GPU、模型和长度上的优化仅能作为选题线索。H20 的带宽、计算与互联边界不同，必须通过独立矩阵决定是否值得启用新路径。

生产影响：先固定产物，随后把灰度拆成三个阶段

推导 / 教学示例
  • 阶段一：保存旧镜像摘要、模型修订、启动命令和依赖解析结果；新环境单独创建，不在原容器里叠装以免混淆身份。
  • 阶段二：检查旧同步开关是否仍在模板、环境注入或启动脚本中；核对实际解析后的参数而非仅搜索主配置文件。
  • 阶段三：固定并行布局与请求集进行故障回归，再逐步开放优化项。P、D 两端及路由器分别记录版本，混版本滚动升级单列验证。
官方事实[4] ↗

冻结依赖声明包含 cuda-python>=13.0、FlashInfer cu13 0.7.2、torch 2.14.1 及 Python 最低版本。它是源码的依赖要求，不是本次检查过的安装解析结果。

推导 / 教学示例

容量观察不要只看请求成功率。失败请求可以已向客户端结束，但其远端责任仍存在；如果仅按客户端活跃数控制 admission，故障期可能持续接入新请求并放大保留页压力。建议同时记录客户端终态、传输终态、ACK 决策和实际页面可复用时刻。

推导 / 教学示例

回滚也要面对在途写入和协议责任。直接重启 D 并复用旧地址是否安全，需要后端级证据，不能由普通应用进程退出推断。这里提出的是回滚测试要求，没有声称该版本提供了自动跨版本回滚协议。
