结论：零数据工作不代表零控制责任

推导 / 教学示例

这项修复连接了两类容易混淆的账：远端资源是否仍等待本次请求结算，以及缓存键是否仍代表当前内容。请求在 D 侧尚未分配就结束，不能据此推断 P 侧没有保留 KV；P 侧少处理一个 token，也不能继续沿用代表较长输入的缓存身份。两者都应在调度层明确处理，而不是等待底层内核“自然收尾”。

官方事实[1] ↗

固定提交同时调整零分配结束通知、截短后 hash 更新，并移除 Python 层不支持的断连调用。

推导 / 教学示例

工程建议是分别验证控制结算与内容一致性，再观察延迟释放占用和服务尾延迟。没有证据证明此次变更带来某个吞吐百分比，也不能从一个 mock 单测推断生产网络下的 ACK 必达。

背景：P/D 之间既传数据，也转移责任

推导 / 教学示例

在分离推理里，P 完成计算并不总意味着它可以立即重用相关页面。D 是否取走、拒绝或不再需要这些状态，是另一条控制协议的职责。如果只有真正进入 worker 的任务才会发结束通知，那么在更早阶段被拒绝的请求就可能绕过通知路径，留下等待超时的远端责任。

推导 / 教学示例

另一种边界发生在状态模型的输入处理：为了阶段衔接调整 token 序列后，缓存身份必须跟着改变。哈希不是一个仅影响性能的装饰字段，它参与决定哪些状态可被当作相同前缀复用。内容变了而身份不变，最危险的结果不是命中率差，而是错误的等价关系。

推导 / 教学示例

这里讨论的是 vLLM-Ascend 的 Mooncake V2 代码路径。真实部署还依赖 vLLM 核心、Mooncake 版本、CANN/驱动及具体 NPU；不能把它自动套用到 CUDA、NCCL 或 H20。

机制：结束通知和缓存身份分别闭合

官方事实[2] ↗

pull scheduler 的结束回调在 do_remote_prefill 仍为真时，按远端字段排入完成通知队列，随后清除标记并返回不延迟本地释放。正常分配路径会先清除同一标记，避免再走这条补偿入口。

官方事实[2] ↗

通知线程会发送 DONE_RECVING 并校验 ACK；异常日志明确依赖 P 的延迟释放超时。缺少远端字段的路径只警告但仍清除标记；字段存在也不等于字段值正确。

推导 / 教学示例

因此监控应至少区分“排入队列”“发送/回复成功”“远端责任结清”“页面可重用”四个时刻。把第一个时刻标为 transfer_success 会制造错误安全感，也会掩盖控制网络压力。

官方事实[3] ↗

base scheduler 在满足状态模型截短条件时移除最后 token，调整计数，清空旧 block hashes 并调用更新，再设置已截短标记。该操作位于本地 prefix 查询之前。

推导 / 教学示例

原创教学例：输入 [a,b,c,d,e] 改为 [a,b,c,d] 后，即使仍保留完整块前缀，也应由实际 hash 规则重新决定可用键。不能凭肉眼认定“只删尾 token，不影响任何整块”，因为块边界、额外 hash 输入和状态模型规则可能改变复用资格。此例不是实际 hash 算法或实测结果。

取舍：补偿控制路径减轻超时等待，也引入独立可观测面

推导 / 教学示例

把早期退出从 worker 路径中分离是合理的：没有必要为了发送终止信号而伪造一次数据传输。但新控制入口也需要自己的队列长度、发送失败和身份关联观测。请求已结束并不意味着后台工作可以无人管理；大量早拒绝可能把负载从数据面转移到控制面。

推导 / 教学示例

清除一次性标记有助于避免重复安排，但它不是分布式事务。消息丢失、进程退出、对端已清理等场景必须依赖协议本身的幂等性与回退设计，不能靠本地 bool 推出恰好一次。

推导 / 教学示例

重建 hash 带来额外 CPU 工作的可能性，但这里没有成本数据。正确性应先通过，再测实际长 prompt、缓存命中率与调度 CPU 时间。不能为了省一点未经测量的开销，接受内容和身份不一致。

生产影响：长尾占用不一定来自 KV 带宽

推导 / 教学示例

原创故障假设：在 D 容量紧张或请求早期取消时，P 的延迟释放占用升高，但网络字节数没有同比增加。此时要检查“已终止但远端仍待结算”的请求，不应先把问题归咎于 RDMA 吞吐。对照正常完成、分配后取消和分配前取消三种路径，才能看见缺失责任的位置。

推导 / 教学示例

缓存侧的异常可能表现为只在特定 prompt 长度或状态模型出现差异。诊断应保留模型身份、token 序列长度、实际块粒度、截短前后 hash 数量以及 prefix 命中结果，使用合成公开输入。不要把用户内部 prompt 或客户日志带入公开报告。

推导 / 教学示例
  • 灰度固定 vLLM/Ascend/Mooncake/CANN 与驱动身份，先验证实际产物包含提交；不以发布时间推断依赖匹配。
  • 记录通知入队、发送成功、远端确认和 KV 可复用之间的分段延迟，遇超时要区分排队、连接、ACK 与释放延迟。
  • sleep/wake 或注销内存回归单独安排，不能用请求取消测试代替注册生命周期测试。
  • 若 hash 参考对照不一致或资源提前复用，立即停止放量并回到已验证版本；不通过加大超时掩盖语义错误。
