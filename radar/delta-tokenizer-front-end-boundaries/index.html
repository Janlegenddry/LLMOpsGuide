一、结论：先把首字延迟拆到CPU入口

推导 / 教学示例

这篇论文值得作为H20/SGLang入口诊断的新线索。建议先回答两个问题：请求到底在哪里等待；测试所需实现是否已经可获取。没有目标机证据前，不应把一种前端优化升级为GPU容量承诺。对NPU服务，同样可以建立入口时间账本，但不能据此认定特定适配器、模型或算子已经兼容。

作者报告结果[5] ↗

论文于10月14日提交；作者说明分块并行、CPU池和SGLang适配器尚待发布。

待验证

本文提出的是隔离实验和接入验收设计。所有表格里的测试都未执行；没有安装依赖、启动模型或访问用户电脑。可先补充观测，拿到完整制品后再决定是否做对照。

二、背景：先定义“请求完成了哪一层”

推导 / 教学示例

一个前端接受HTTP请求，并不等于后端已经接受同一个推理任务。建议为一次请求定义到达、模板完成、ID生成、模型准入、GPU排队、首token六类事件，用同一关联ID串起来。这样，模型队列很短却TTFT很高时，才有证据继续向入口查，而不是立即调整通信或KV容量。

推导 / 教学示例

以下是原创反例：两个测试都说每秒处理十个长请求，一个最后返回长度错误，另一个生成完整答案。两者会给CPU和GPU留下完全不同的工作量。不能拿入口吞吐当完成吞吐，也不能把错误返回速度混入正常首token指标。

推导 / 教学示例

字符数、字节数、token数分别记录。跨语言或模板变化后，同样字符数未必形成同样模型负载；输入长度应使用最终交给引擎的实际ID计数。

三、机制：文本状态、ID状态与KV状态分别验收

作者报告结果[1] ↗

论文核心是保留旧ID、修复追加处尾部，在安全切点并行完整编码，并按块调度短更新。

作者报告结果[2] ↗

TokTier标签文档将追加结果定义为TokenPatch：先按keep_tokens截断旧ID，再拼replacement_ids；完整快照另取。

推导 / 教学示例

由这个接口可提出接入不变量：消费者的最终ID数组必须等于同配置参考编码；“新文本”不能直接被理解成“只追加ID”。若接入层还维护自己的token缓冲、长度计数或KV索引，每个派生状态都必须在同一请求版本下更新。本文不主张直接修改引擎KV，只要求通过原有已验证入口提交最终输入。

推导 / 教学示例

原创示例：缓存版本a算出了一个修补结果，但版本b先到达。此时应拒绝过时提交或按明确顺序处理，而不是把两个补丁依次盲拼。下面图描述拟议接入验收，非论文系统架构复刻。

五、取舍：把优化后的新瓶颈也算进去

推导 / 教学示例

原创成本账本应同时覆盖CPU核时、保存会话的主存、完整ID物化与序列化、队列等待、GPU工作和失败重试。减少某一段计算，可能只是让下一段更早接到请求。闭环压测会随响应加快自动增加供给，因此既要测闭环容量，也要用固定开放到达流比较同等压力下的延迟。

推导 / 教学示例

假设前端省了20毫秒，但模型排队增加30毫秒，那么用户感知仍可能变差。这只是教学数字，非论文测量。若短请求变快而长请求持续排队，也不能仅宣布总体P99改善；至少同时报告各长度组、冷暖组、首次请求和后续轮次。

作者报告结果[2] ↗

持久化会话另有隐私和容量成本。标签文档明确持久存储包含恢复用的文本，应按应用数据保护。

推导 / 教学示例

本文建议在试验中只使用公开或合成输入，诊断日志存不可逆标识和计数；不要为提高可观测性而收集真实用户全文。

推导 / 教学示例

对H20与Ascend都先确认CPU架构、亲和性、容器核配额和内存带宽约束。相同模型后端不意味着相同前端瓶颈；同一套CPU参数也未必适用于两种部署。没有相应机器证据，本报告不选择核心数、chunk大小或并发默认值。

七、实验：一次只改变一个可解释的因素

未执行实验矩阵；先冻结参考编码与实际服务版本
编号设计记录与停止条件依据
E0 制品获取论文适配器、版本、依赖和启动参数；核对当前公开交付关键组件缺失就停，不用替代实现冒充复现。待验证
E1 语义追加、中途编辑、模板变化、特殊token、Unicode组合、空输入同配置逐ID一致；发现任何差异立即停止性能试验。待验证
E2 状态同会话并发、乱序、取消、重启、状态驱逐版本不串线、终态有界；参考回退路径单独计数。待验证
E3 入口参考、只换编码器、状态复用、完整池分阶段比较固定输入与核预算，记录编码/排队/物化成本。待验证
E4 服务冷/暖前缀×长背景被拒/实际服务×开放/闭环到达正常与拒绝分母分开，TTFT/TPOT/goodput全部记录。待验证
E5 公平持续短更新混合冷长文，并扫核配额与会话数同时记录长文最大等待、错误率及主存；不能牺牲某组换总体指标。待验证
E6 迁移在目标H20和NPU各自固定后端做独立对照先验证CPU前端可接入，再谈收益；不复用另一硬件结论。待验证

八、验收：正确性、可恢复、效益分别过门

拟议门槛，具体SLO需在试验前登记
维度通过标准不能替代的信号依据
输入契约所有约定测试逐ID一致，配置身份可追溯输出可读或token总数相同。待验证
生命周期乱序和重启不污染状态；取消后资源与后续请求恢复进程存活或一次重试成功。待验证
可归因每次请求标出执行路径、分段时间和准入结果全站平均TTFT。待验证
有效服务固定到达流下预登记SLO与错误预算达标；各请求组不饥饿只展示最有利峰值倍数。待验证
成本按SLO内完成任务计CPU、主存、GPU与重试的总成本只看分词微基准或GPU利用率。待验证
推导 / 教学示例

建议用同批输入随机交错或独立重复实验，并公开样本量、运行时长、冷暖条件与分位数计算方式。若只有几十个请求，不要靠一个p99数值做生产决策；需要覆盖突发、回退和长等待尾部。

九、待办：先验证入口，再决定是否接入

待验证

待取得论文完整复现制品；待核查目标SGLang版本的真实入口与会话接口；待做H20、NPU CPU前端独立基线；待实测持久状态成本与并发恢复。上述未知不由TokTier既有版本号、论文摘要或通过静态JSON校验来消除。

推导 / 教学示例

若业务的大部分时间仍在模型prefill或decode，先保留入口观测即可。若入口占比与长文阻塞确实显著，再推进小规模语义验证。这样能把新论文变成一个可证伪的工程问题，而非一个未经复现的上线承诺。
