InferRSI v0.3.0：先定位瓶颈，再验证 Agent 调优值不值

原文 2026-11-21核对 2026-11-22

新版本把瓶颈诊断、知识开关配对和胜出候选复验串起来。对照公开的 H20 历史失败案例，解释为什么软件发布、单点跑分和生产可用是三回事。

一、结论：新版本让优化过程更可审计，不证明推理已经变快

作者报告结果[1] ↗[2] ↗[3] ↗

InferRSI v0.3.0 于 11 月 22 日北京时间发布，对应提交 af836963（11 月 21 日 20:23 UTC）。新增或整理了先测瓶颈再试、知识库开关的独立会话比较、候选服务复用及最终独立验证。发行记录把这些能力与真实 campaign 验收明确区分。

推导 / 教学示例

值得借用的是三道门：对照是否可比，候选输出是否正确，达标收益能否在没参与搜索的数据上复现。模型和 GPU 不换的前提下，先交付这条验收链比先承诺自动优化百分比更稳。

二、背景：要证明是知识库在帮忙，不能只比两个最快结果

推导 / 教学示例

候选生成和评测系统都可能改变结果。在同一会话先看 A 再跑 B，提示和探索路径会泄漏；在同一批输入上选最高分再汇报，搜索波动会被误当改进。需要给两臂同样的机会，再用未参与选优的流量复验。

作者报告结果[1] ↗[2] ↗[9] ↗[10] ↗

发布默认比较昇腾上的 Qwen-Image 2.1 去噪与 MoE forward。一轮 repeat 是两任务各开、关一次，共四个独立 Agent 优化会话。指南对应一张或两张 NPU；默认 8 个候选轮次与 60 分钟 campaign 预算，不是 H20 文本生成性能或生产 SLO。去噪是带随机权重的单流代理任务；MoE 是双 NPU 的一层前向，包含 HCCL 通信与本地专家算子；两者都不是完整模型服务。

三、机制：诊断、独立搜索、候选筛选与终轮重验

作者报告结果[2] ↗[3] ↗[7] ↗[8] ↗

对两臂都先登记来自冻结基线或同环境同负载的测量。受管知识检索和候选轮次关联诊断；服务复用遇到新的参考条件时，要登记对应阶段。每臂在隔离工作区使用冻结任务，主控通过宿主工具确认真实会话，不靠 CLI 伪造会话标识。源码约束摘要和 reference epoch 的留档，不验证瓶颈的判断一定正确。

作者报告结果[2] ↗[7] ↗

关闭组移除受管知识数据与对应检索，其他知识来源由共同指令限制，并非操作系统沙箱。配对要求实际模型、推理 effort 和运行环境指纹匹配；宿主观察要有原始回执，字段本身不是独立认证。入选代码分别重跑终轮，缺失或无效配对报告证据不足。

五、取舍：快一点的候选可能反而更贵

作者报告结果[2] ↗

比较默认同时看优化后最终加速和实际 campaign 用时，可用完整口径再比较模型 token 开销。小样本的相对容差不是显著性检验；按任务报告配对结果，不把不同任务的耗时混成一个均值。

推导 / 教学示例

业务账建议拆成：搜索阶段消耗的加速卡时、人工复核成本、上线后的达标吞吐和尾部风险。与只调已有参数相比，更大搜索空间可能找到更好候选，也会增加抽到假阳性和维护分支的成本。缺失数据不能默认为零成本或零故障。

六、生产边界：先让工具出建议，发布控制仍独立

推导 / 教学示例

候选从开关比较中获益，只回答受管语料是否改善这项优化任务，不回答候选能否应对真实的长会话、热冷缓存或排队尖峰。使用候选前冻结镜像和版本，确认长答/工具终态、流式取消、排队与配额符合预定门槛，再进入有审批的实流灰度。

推导 / 教学示例

采集按客户端可见首输出、ITL、终态与资源结算拆开。若首个事件只是 role、空段或 reasoning，而业务需要正文或完整工具参数，不能以它作为任务达标。真实流量只使用已批准用途的脱敏数据，工具无生产写权限。

九、待验证：还没有生产收益或跨栈外推

待验证

待核实不同随机性和负载窗口的重复性；受管语料开关是否在本地部署真正隔离；被选候选在文本生成、P/D、真实网关路径与 H20/昇腾部署的功能、性能和成本。本文没有执行任何优化、访问内部数据或改变线上配置。
