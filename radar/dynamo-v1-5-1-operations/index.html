结论

官方事实[1] ↗[15] ↗

Dynamo v1.5.1 于 2026-10-07 01:54 UTC 发布，属于正式补丁版本。

推导 / 教学示例[1] ↗

此次最值得关注的是过载后重新接流的状态管理，以及 tokenizer-free SGLang 请求的停止与取消语义。适合把它作为恢复正确性升级评估；现有证据不足以给出通用吞吐提升比例。

推导 / 教学示例[1] ↗

建议按实际部署路径分组验证。标准 Python decode、sidecar、多模态和 GPU Memory Service 不能互相代替验收。

官方事实[1] ↗

尤其要注意：发布说明仍列出 SGLang sidecar 每次推理 HTTP 500 的已知问题，以及部分 H.264 输入造成 worker 崩溃的问题；两项修复目标均为 v1.6.0，不能把目标版本当成已经交付。

背景

推导 / 教学示例

推理服务出现“GPU 已空闲，客户端仍被拒绝”的情况时，算子耗时通常不是第一条排查线索。一次容量拒绝会改变路由侧对 worker 的判断；如果拒绝留下的状态没有及时失效，真正的压力已经消失，流量仍进不来。读懂这次补丁，需要把三个问题分开：worker 是否被发现、是否允许路由、当前是否被标记过载。这是本文的运维分析框架，不是新增的产品承诺。

推导 / 教学示例

另一类问题发生在请求结束边界。客户端已经看到终止，并不等于后端所有并行分支都停止执行。对于最小生成长度、提前停止和多候选生成，必须分别观察输出语义、后端生成和资源释放，不能只看 HTTP 状态。

官方事实[1] ↗[12] ↗[13] ↗[14] ↗

新增事实是 10 月 7 日的版本交付。相关上游 PR 在 9 月已有合并：路由 #14210 为 9 月 9 日，SGLang #14276 为 9 月 17 日，GMS #14877 为 9 月 16 日。

推导 / 教学示例[2] ↗[3] ↗[4] ↗

本文不将这些补丁描述为 10 月首次发现的问题。

机制

请求路径过载提示与监控状态

官方事实[5] ↗

v1.5.1 的 Client 源码保留两组信息：监控上报的过载集合，以及请求路径产生的过载截止时间。后者冷却常量为一秒。候选集合计算使用两类信息，清理到期提示不会顺便清除监控上报的过载状态。新监控更新也能提前替换请求提示；到期清理在读取路由快照时检查并协调，并非定时强制探活。发现列表变化时，相应状态随 worker 生命周期协调。

推导 / 教学示例

这意味着“一秒后提示过期”只恢复一次重新考虑该 worker 的机会。它不保证 worker 在一秒内完成排空，也不保证排队、网络、引擎或模型已经恢复。验收要分别设置“提示过期时刻”“再次选中时刻”和“首个成功响应时刻”，避免将不同阶段压成一个恢复时间。

tokenizer-free 路径的最小长度与退出

官方事实[6] ↗

已发布的 decode handler 在无 tokenizer 的 token 请求路径中，遇到正的 min_tokens 且 skip_tokenizer_init 开启时，不再向 SGLang 传递正的 min_new_tokens，并让引擎忽略 EOS、移除该路径的引擎 stop token 集，交由 Dynamo decoder 判定结束。max_tokens 仍进入后端参数。

官方事实[3] ↗

PR 明确把最小长度兼容限定在非 native 的 DecodeWorkerHandler token 路径；不应外推到 sidecar、native passthrough 或专用多模态 lowering。它还说明 chunk 内停止时需对齐截断 token 相关字段，并忽略已经完成候选的后续 chunk。

官方事实[6] ↗[7] ↗

取消逻辑通过每个候选的后端 ID 跟踪未完成集合，已经完成的 ID 从集合移除。token 与 text 流退出时均有取消清理，取消后迟到的 ID 也需要处理。

推导 / 教学示例[6] ↗[7] ↗

这是后端代码中的请求级清理设计，不等于已经证明 KV、显存和所有外部传输在任意故障下都无泄漏。

权重入场超时的边界

官方事实[1] ↗[11] ↗

GMS #14877 将操作者已经配置的 gms_ro_connect_timeout_ms 传到初始 vLLM 权重客户端创建。没有配置时仍可能无界等待。最终补丁没有新增默认超时，也没有证明或修复一个通用死锁。PR 中早期方案比最终范围大，阅读历史时应采用最终摘要与发布结果。

取舍

推导 / 教学示例

过载提示的自动失效降低“永远拒绝”的风险，但重新尝试可能发生在 worker 尚未恢复时。因而应同时关注恢复速度与重复拒绝数量，而不是只追求更短冷却。这里是机制推导，未声称存在新的可调参数。

推导 / 教学示例[3] ↗

为了保证最小生成长度，Dynamo 接手停止判定后，后端可能继续生成最终不会交付给用户的 token。这使输出正确性、生成开销和取消响应成为同一个实验中的三个维度。客户端 token 数少并不能证明后端计算少。

官方事实[8] ↗

HTTP 客户端现在统一到 aiohttp。固定版本的 HTTP 说明指出，旧的 httpx 专用连接参数仍被接受但被忽略；保留旧环境变量不代表保留原行为。

推导 / 教学示例[8] ↗

建议迁移前导出实际生效配置，再对远程媒体扇出请求单独压测，不引用其他业务的 HTTP benchmark 作为本服务收益。

生产故障关联与部署兼容

官方事实[8] ↗

媒体请求经过环境代理时，升级可能变成明确拒绝。DYN_MM_TRUST_EGRESS_PROXY=1 表示部署方信任代理自己执行目标访问策略；它不只是一个消除错误的开关。NO_PROXY 命中的直连情况有不同路径。

推导 / 教学示例[8] ↗

应由部署与安全负责人确认实际出口，避免为了恢复请求而放宽全局策略。

官方事实[9] ↗[10] ↗

SGLang diffusion 的本地 input_reference 需要配置 DYN_MM_LOCAL_PATH 允许目录。远程引用先落临时文件后交给生成器；下载默认上限为 64 MiB，由 DYN_MM_MAX_FILE_SIZE_MB 调整。

推导 / 教学示例[9] ↗[10] ↗

应验证容器内路径、挂载和临时存储，不把宿主机目录写法直接照搬。
