SGLang Decode Radix：请求都成功之后，KV 为什么仍可能双重归属

原文 2026-10-14核对 2026-10-15

10月14日合入的 #40857 将插入后所有权与 SWA 命中资格分开。固定源码拆解 bigram 页边界、canonical 索引重绑和 EAGLE3 准入；用多轮空闲审计与逐页验收设计解释为何 HTTP 200 不足以证明安全。

推导 / 教学示例

这次值得关注的是 decode 侧缓存生命周期，而不是一个新的吞吐成绩。设想缓存树已接管一段请求 KV，随后一次“这段还能用于新请求吗”的查询返回更短前缀。如果系统据此缩短“请求不再有权释放的范围”，就把读资格错误地当成了所有权证明。本文建议把缓存准入、请求结束、空闲池审计连成一次完整验收；请求成功返回只能覆盖其中一站。

阅读范围与判重

推导 / 教学示例

此前 Unified Radix Cache 阅读条目 聚焦多组件复用边界。本篇独立讨论 PD decode 插入之后的所有权交接：为何未命中仍可能持有树资产、怎样构造短窗口回归，以及怎样在请求完成后发现双重归属。不是对旧条目的改名重发。

背景：HTTP 200 为什么不能替空闲池签字

作者报告结果[10] ↗

作者报告：1P/1D、gpt-oss-120b、SWA、64-token 页与 EAGLE3 的多轮请求均返回 HTTP 200，随后 decode scheduler 在空闲审计中失败。其 FULL 池出现 6 页、SWA 池 1 页同时被树引用和空闲链表持有。作者的单轮对照没有触发同类错误；这些是作者现场描述，本站未独立复现。

推导 / 教学示例

多轮负载和独立单轮负载，最大的区别未必是平均输入长度。前者把上轮 decode 生成的内容重新纳入下一轮输入，让“刚写过、刚挂树、又被匹配”的路径高频重逢。只压相同长度的随机 prompt，即使达到相同 token 吞吐，也可能绕开这个状态交接。测试设计应保留真实 token 历史，不能只让字符串看起来相似。

推导 / 教学示例

接口结束、请求对象释放、缓存保留和 allocator 空闲不是同一事件。缓存是有意留下来的已用资源，不能期待每轮结束后空闲量完全恢复；相反，也不能因为树里还留有可驱逐页就放弃守恒检查。正确的问题是：每个物理页此刻由谁负责，允许谁发起最终释放，下一次分配会不会把它交给另一个请求。

两个容易混淆的“通过”

推导 / 教学示例

树内部计数自洽，只说明树自己讲得通；空闲链表没有重复页，只说明分配器自己讲得通。两个集合各自干净，也可能有交集。审计必须跨越对象边界，验证同一个物理页不能同时是树资产和可重新分配的空闲资源。

机制：树已经拥有，不代表窗口已经可复用

官方事实[3] ↗

固定实现不再用插入后的 _match_tree 结果决定重绑节点，而采用 insert 返回的 last_device_node。path_device_indices 从该节点收集至根的设备索引；断言同时检查插入重叠长度不越界、索引数等于 page_aligned_len。随后写回请求索引，迁移锁并更新 cache_protected_len。

官方事实[5] ↗

SWA 的普通匹配验证器遇到缺失组件数据会重置有效累计长度，再以滑动窗口大小判断边界；源码也有 host-backed 与 per-request ring 的特殊处理。因此本文的“短窗口会被拒绝”限定在对应设备树状态，不能套到所有 SWA 存储模式。

官方事实[4] ↗

RadixKey 的 bigram 视图对 n 个原始 token 产生 max(n−1,0) 个键；page_aligned 按键长度向下取整到页粒度。这里对齐的是键空间，不是把原始 token 数直接除以页长。

原创数值推导：减一可能少整页

推导 / 教学示例

取教学参数 n=256、页长 P=64，普通键可插入长度是 256，bigram 键则是 floor(255/64)×64=192。若某个假想请求仅在 [160,256) 持有活的 SWA 内容，插入区间内的活尾就从 96 缩到 32。假设所需完整窗口为 64，这个尾部不足以支持新的匹配，却不否定此前完成的插入交接。数字只说明离散边界效应，不复刻作者现场或实际传输分配。

推导 / 教学示例

因此应该分清至少三个长度：原始输入覆盖长度、页对齐后插入键长度、对某次查询可复用的前缀长度。还有一个独立事实是 canonical 物理索引序列：发生重复前缀合并时，请求原来分配的页未必就是树最终持有的页。只更新计数而不重绑地址，或只重绑地址而不更新保护范围，都没有完成交接协议。

推导 / 教学示例

这并不意味着“把保护长度永远拉满”就是通用修法。插入可能存在拒绝分支，组件也可能对可缓存长度施加限制。正确目标是仅覆盖已经被该次插入实际接管的规范路径，并在继续清理之前验证覆盖关系；不能拿希望写入的长度替代已完成的所有权事实。

证据：最小回归故意保留零命中

官方事实[6] ↗

新增定向测试使用 SWA、无 Mamba、page_size=1、window=4；构造 8-token 请求，先释放 [0,6) 的 SWA，只留两个活 token。checkpoint 后检查完整插入保护，另做新匹配仍期望 device_prefix_len=0；结束请求后核对 FULL/SWA 的 available+evictable 各回到初始容量。本文只阅读测试，没有运行或推定 CI 结果。

推导 / 教学示例

定向回归最有价值的地方是没有把“提高命中”当成修复条件。如果新的测试靠放宽 SWA 匹配规则来通过，就可能从资源错误换成上下文缺失：资源不再被早释放，但后续计算读取了不足的历史窗口。这里应分别验证两条不变量，一条守护未来计算的输入完整性，另一条守护过去插入的资源责任。

负证据也要保留

推导 / 教学示例

未运行测试、未核实 CI 终态、未核实发布标签，都是证据缺口。不要把 PR 合并、测试文件存在、某次普通压测成功拼成“生产问题已解决”的合成结论。

取舍：允许启动只是准入第一关

官方事实[7] ↗

固定 speculative_hook 在别名解析后检查最终算法：decode radix cache 允许 None、DSPARK、EAGLE、EAGLE3。NEXTN 通常映射为 EAGLE；Gemma4 assistant draft 可将 NEXTN/EAGLE 转为 FROZEN_KV_MTP，因此不能仅凭用户输入的别名判断可用。

官方事实[8] ↗[9] ↗

对应字段的 decode radix cache 默认值仍为 False。PD hook 保留与 HiSparse、fake transfer 的冲突检查，并把启用状态标为 experimental；DP attention 场景还提示需要 prefix-aware rank routing 才有理想命中。

推导 / 教学示例

对多轮 agent、会话续写或长历史重复请求，D 侧保留前缀的潜在价值是少搬运已经在 D 的 KV。但多保留一页，也意味着少一页能立即承接新请求。最终应按真实峰值并发下的服务目标决策，而不是把更高 hit rate 或更少传输字节直接折算为用户可见加速。

推导 / 教学示例

比较时建议分离四个因素：缓存开关、投机开关、请求历史重用程度、页/窗口相对边界。一次同时换模型、后端和投机深度的升级，即便性能更好，也难以解释收益来自哪里；即便稳定性变差，也容易错怪这条所有权修复。

待验证

H20 的实际显存压力、目标模型支持与通信路径需要独立配置验证；Ascend 还应分别确认分支实现、算子和 PD 后端支持。共享 Python 逻辑或算法 allowlist 都不能替代端到端平台证据。Mamba、ring、HiCache 恢复、retraction 等扩展组合也不在这条小型回归的证明范围。

生产推演：不要等下一次空闲才留证

推导 / 教学示例

下列均为原创故障假设与拟议诊断路径，不代表已观察到的新漏洞。建议在隔离回归中用页身份、池类型与分配世代构建事件账本；不要只记录总 token 数。FULL 与 SWA 的相同数值索引不能当成同一物理页，分配器重用同一页号后的新世代也应与旧世代分开。

推导 / 教学示例

观测窗口应越过最后一个客户端响应：先等请求和传输队列安静，拍一次快照；再执行受控驱逐或新一轮复用，拍第二次快照。这样能够分开“资源归属错误”与“错误尚未变成可见覆盖”。若只能在故障后抓取现场，重复分配可能已经覆盖了第一个冲突的证据。

诊断开销与数据边界

推导 / 教学示例

逐页跟踪会改变时序并增加开销，应保留轻量计数模式与深度审计模式两套回归，不能拿审计模式的延迟评估正式性能。日志只存合成请求编号、页身份和 token 历史摘要；不需要上传真实会话正文。

推导 / 教学示例

若检测到树持有页同时进入空闲集合，隔离该实例并保留证据应优先于继续压测。不要把释放同一页第二次当作“纠正计数”；不要通过关闭断言掩盖不变量失败。回退目标应是已验证基线，而不是任意关闭投机后就宣称根因消除。

计算正确性固定历史的无缓存参考，预先规定精度与采样口径无新增错误或不可解释输出分歧停止放量，定位首次差异待验证
服务价值相同负载下 TTFT/TPOT/端到端尾延迟、错误率、有效吞吐满足原 SLO 且收益足以覆盖容量与复杂度成本保留修复但是否启用功能另行决定待验证
推导 / 教学示例

守恒表必须是互斥分类。树上被锁定的页可能仍由活动请求引用，但这不等于两个可自由释放的所有者；“引用”与“释放责任”要分别定义。对可驱逐页、被保护页和会话持有页，应依实际实现明确是否包含关系，再决定如何求和。直接照抄告警里的几个数字相加，很容易制造假泄漏。

推导 / 教学示例

建议最终交付一份证据包：版本身份、解析后配置、边界覆盖清单、首个冲突事件或空集合快照、结束后的池状态、独立正确性对照与服务指标。没有这样的证据包，最诚实的结论只能是“指定测试暂未触发”，不能升级成“所有 PD 投机配置可安全启用”。
