FlashInfer 2-CTA TGV：算完自己的矩阵，不等于可以退出

原文 2026-11-11核对 2026-11-11

主干为 BF16 TGV 的 2-CTA 路径补上退出 cluster barrier，保护对端仍需访问的 CTA 生命周期。正式 v0.7.4 标签仍未含该栅栏；作者单 B300 数值与微基准不能替代多卡 Graph+PDL 故障复现。

结论：协作对象的寿命也是正确性条件

推导 / 教学示例

两个 CTA 共同处理一个矩阵 tile 时，某一侧“我的算术已经完成”只是一条局部事实。另一侧可能还要向它的屏障或共享状态发送尾部操作；如果前者已经退出，后者面对的不是一个较慢消费者，而是一个已经不存在的协作对象。退出边界因此必须与协作范围一致。

官方事实[1] ↗[2] ↗

冻结提交为 TGV CuTe BF16 kernel 的 use_2cta 分支增加尾部 cluster_arrive_relaxed 与 cluster_wait。代码位于 warp dispatch 之后，不进入 1-CTA 编译路径。

官方事实[4] ↗[5] ↗

最容易误判的是版本：11 月 11 日可见正式 v0.7.4，但该标签的对应文件仍仅有入口 cluster 同步，未包含此次退出栅栏。应核对实际 kernel 内容和产物来源，而非把“最新版本”当修复证明。

背景：入口同步解决出生，退出同步解决寿命

推导 / 教学示例

入口 cluster barrier 解决的是协作开始时双方已准备好，不能把这项保证延伸到结束时。随着独立 warp 工作、异步数据移动和不同资源竞争推进，最初同时进入的两个 CTA 仍可能在不同时间走到末尾。协作越接近结束，依赖的次数可能越少，但只要还存在一次对端操作，生命周期要求就仍在。

推导 / 教学示例

当部署允许前后继 kernel 重叠时，额外资源竞争可能拉开两个 CTA 的完成时刻。需要分别检查 kernel 之间的数据依赖，以及同一 cluster 内参与者的退出条件；前者的优化许可不构成后者自动安全的证明。

推导 / 教学示例

对排障而言，PDL 是一个可能改变调度相对时机的条件，不是所有 Xid 13 的通用解释。先定位错误 kernel、tactic 与 cluster 路径，再讨论完成顺序。没有这些身份信息，随意关闭整个优化栈很难形成可验证的归因。

机制：退出栅栏放在共同尾部，不能插错位置

官方事实[2] ↗

冻结实现的每个 CTA 有 256 线程，即八个 warp。DMA、MMA 与 epilogue 走各自分支；2-CTA 入口已有 cluster 同步。尾部新增栅栏位于所有分支汇合之后；MMA 路径先等待本 CTA epilogue 的既有 mbarrier 阶段，再调用带 is_two_cta 的 dealloc_tmem。

推导 / 教学示例

原有 mbarrier 管数据阶段，新增 cluster barrier 管 CTA 退出资格。这是两种不同的证明：一个说明某项操作满足了协议，另一个说明参与者尚未离场。不能因为存在退出栅栏，就删除已有的数据完成等待；也不能认为已有数据屏障会自动延长所有对端 CTA 的寿命。

官方事实[2] ↗

位置同样是语义的一部分。若某侧先进入新栅栏，而另一侧仍在等待前者参加 TMEM 的成对释放，就可能把原来的退出竞态改成等待环。源码明确将栅栏放在双方 dealloc 之后。移植时必须保留这个先后关系，而不是搜索函数末尾后随意插入一条同步指令。

作者报告结果[3] ↗

作者报告没有确定性复现器，单卡 B300 未重现该竞态。所列计时选取 base/fix/fix/base 各臂两次运行中的较小值，汇总几何均值约 1.008 倍、最差约 1.017 倍；基线自身个别形状波动可达 2.4%。这些数字只能描述那组微基准，不能被转写为生产开销上限。

推导 / 教学示例

对罕见调度错误，无法复现既不是修复无效的证据，也不是修复完成验证的证据。源码分析说明修复针对哪一条寿命缺口；针对真实部署的压力试验还需回答覆盖是否足够。

取舍：局部提早退出换成协作范围内的等待

推导 / 教学示例

新增等待可能让先完成的一侧多驻留一段尾部时间。这不是无条件性能优化，而是让资源退出与协作责任一致。应比较同一 backend、同一 tactic、同一 PDL 设置下的延迟变化，不能让自动调优同时换了算法后再把全部差异归给 barrier。

推导 / 教学示例

1-CTA 分支没有新增栅栏，可作为有帮助的负向对照，但它与 2-CTA 的工作划分、资源占用并不完全相同。因此“1-CTA 不崩、2-CTA 崩”只是定位线索，而不是等成本性能对照或根因的独立证明。

推导 / 教学示例

实际部署还存在源码副本和编译缓存边界。主仓库修复、框架内 vendored copy、已编译 kernel 与本机缓存是不同对象；必须记录真实被调用对象，避免在修好的源码旁边继续运行旧产物。这里提出的是验证要求，不声称任何特定缓存机制已经发生错误。

待验证：把“没有重现”留在正确的证据等级

待验证
  • 本站未进行任何 B200/B300 GPU、CUDA Graph、PDL 或业务验证。
  • 作者没有确定性复现器；单卡测试通过不证明原多卡压力条件下的竞态已被覆盖。
  • v0.7.4 正式标签未含该退出栅栏；后续正式版本、wheel、框架依赖 pin 与缓存产物需继续核对。
  • relaxed arrive 的使用依赖既有数据阶段协议；此修复不能替代对任意新跨 CTA 访问的独立顺序证明。
  • 未测不同 tactic、形状、拓扑与实际服务负载下的长尾和成本。
推导 / 教学示例
